1. Fichiers Unix

  • Descripteurs ouverts d'office : 0 stdin, 1 stdout, 2 stderr. open renvoie le plus petit libre, ou -1 (errno, perror).
  • read(fd, buf, n) renvoie le nombre d'octets lus, 0 en fin de fichier, -1 en erreur : on boucle tant que le résultat est > 0. lseek déplace la position, dup2 redirige.
  • Inode : droits, propriétaire, taille, dates, adresses des blocs, nombre de liens. Pas le nom (il est dans le répertoire).
  • Lien dur = même inode (le fichier disparaît quand le compteur tombe à 0). Lien symbolique = son propre inode, contient un chemin, peut « casser ».

2. Makefiles

prog: main.o util.o
<TAB>gcc -o $@ $^
%.o: %.c util.h
<TAB>gcc -c $<
.PHONY: clean

$@ la cible · $< la première dépendance · $^ toutes les dépendances. make reconstruit une cible absente ou plus ancienne qu'une de ses dépendances.

3. Processus et signaux

AppelÀ retenir
fork()0 dans le fils, PID du fils dans le père, -1 si échec. Les deux continuent après l'appel.
exec*()remplace le programme, garde le PID, ne revient pas si succès.
wait / waitpidrécupère le statut du fils (WIFEXITED, WEXITSTATUS) et évite le zombie.
kill(pid, sig)envoie un signal ; pid 0 = le groupe ; sig 0 = tester l'existence.
sigaction()installe un gestionnaire (préférée à signal()).

Zombie : fils terminé, pas encore attendu. Orphelin : père mort, adopté par le PID 1. SIGINT (2) = Ctrl+C, SIGTERM (15) = kill par défaut, SIGKILL (9) et SIGSTOP impossibles à capter, SIGCHLD prévient le père.

4. Sockets TCP en C (TP parcours B)

Serveur : socket → bind → listen → accept → read/write → close. Client : socket → connect. socket(AF_INET, SOCK_STREAM, 0) = TCP/IPv4. htons(port), htonl(INADDR_ANY). accept renvoie une nouvelle socket par client. « Address already in use » → SO_REUSEADDR. HTTP/0.9 : GET /chemin, pas d'en-têtes, le serveur ferme après l'envoi.
